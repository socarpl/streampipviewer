# AI Generation Instructions: Stream PIP Viewer

Create a lightweight desktop Stream Picture-in-Picture viewer. The implementation technology is not fixed. Choose any stack that can provide efficient RTSP/H.264 playback, low CPU usage, and reliable desktop UI behavior.

## Core Goal

Build an app that displays two RTSP/H.264 CCTV feeds:

- One feed as the main video.
- One feed as a smaller PIP overlay.
- Default: `CCTV1` main, `CCTV2` PIP.
- Default: both streams start muted.

The app must prioritize:

- Low CPU usage.
- Native or hardware-assisted H.264 decoding where available.
- High visual quality.
- Minimal unnecessary frame copying.

Avoid:

- MJPEG conversion for display.
- Re-encoding H.264 just to show the stream.
- Raw frame pipelines where the app manually receives and paints full-resolution frames.

Prefer:

- Native player/decoder backend.
- Embedded video surfaces.
- Efficient compositor/video overlay pipeline.
- Separate playback worker processes if the chosen backend applies audio state process-wide or otherwise cannot isolate audio per player instance.

## Required Architecture

Use a shell app plus a single-stream host process when implementing with LibVLC, VLC, or any playback backend that may share audio state inside one process.

Recommended Windows implementation:

- Main executable: `CctvPip.App`.
- Host executable: `CctvPip.StreamHost`.
- `CctvPip.App` owns layout, MainWindow/PIP role mapping, context menu, fullscreen, settings, and config persistence.
- `CctvPip.StreamHost` owns exactly one native player instance and plays exactly one stream.
- Launch one host process for `CCTV1` and one host process for `CCTV2`.
- Build the main app so it also builds/copies the host executable and all native playback dependencies into a `StreamHost` subfolder beside the main output.

In hosted mode, the main app should launch hosts similarly to:

```text
CctvPip.StreamHost.exe --hosted --stream cctv1 --label CCTV1 --config <config-path>
CctvPip.StreamHost.exe --hosted --stream cctv2 --label CCTV2 --config <config-path>
```

Hosted process behavior:

- `--hosted` makes the host borderless and suitable for embedding.
- The host should create a real top-level window before or during playback startup.
- The shell app should find the child window by process ID, not only by a framework-provided main-window property that may stay empty for hidden, borderless, or off-screen windows.
- The shell app should embed the host window into the appropriate video surface using the platform's native child-window mechanism.
- The shell app should resize embedded host windows when the main layout changes.
- The shell app should send mute, unmute, restart, and shutdown commands to the correct child process.
- The shell app should preserve per-stream mute state and reapply it after host restarts.
- Closing the main app should close both host processes cleanly, then terminate them if they do not exit.

The host executable must also work as a normal standalone diagnostic app when `--hosted` is omitted.

Standalone host behavior:

- Opens as a normal visible window.
- Reads `--stream cctv1` or `--stream cctv2` and `--config <path>`.
- Allows `--url <rtsp-url>` to override config.
- Allows `--label <text>` to customize the title/status label.
- Starts muted by default.
- Starts unmuted only when `--unmuted` is present.
- Supports right-click menu actions for mute/unmute and restart.
- Supports keyboard shortcuts: `M` toggles mute and `R` restarts playback.

## Default Sources

Use these default source URLs:

```properties
cctv1.url=rtsp://192.168.0.999:554/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
cctv2.url=rtsp://192.168.0.998:554/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
```

Use `subtype=0` by default because it is the higher-quality stream.

## Video Layout

Implement:

- Main video surface.
- PIP video overlay.
- Black background for letterboxing/pillarboxing.
- Aspect-ratio preservation.
- PIP border.
- Default PIP border color: white.
- Configurable PIP border size from 0 to 100 px, where 0 means no border.
- PIP X/Y coordinates relative to the top-left of the main video surface.
- PIP size as a fraction of the main video width.
- PIP clamping so it cannot disappear fully outside the visible video area.

Suggested defaults:

```properties
pip.border.color=#FFFFFF
pip.border.size=2
pip.x=1450
pip.y=40
pip.scale=0.28
```

## Runtime Operations

Implement these operations:

- Swap feeds.
- Mute all streams.
- Unmute all streams.
- Toggle mute for the stream currently displayed in the main window.
- Toggle mute for the stream currently displayed in the PIP window.
- Enter fullscreen.
- Exit fullscreen.
- Open settings.
- Open active config file.
- Change PIP size.
- Change PIP X position.
- Change PIP Y position.
- Change PIP border color.
- Change CCTV1 source URL.
- Change CCTV2 source URL.
- Save settings.
- Cancel settings.

## Mouse And Keyboard Behavior

Context menu on right-click over the video window:

```text
Settings
Separator
Mute All
Unmute All
Separator
Unmute Main Stream / Mute Main Stream
Unmute PIP Stream / Mute PIP Stream
Separator
Swap feeds
Fullscreen
```

Rules:

- Each `Separator` must be a real menu separator line, not text.
- When already fullscreen, the fullscreen item should read `Exit Fullscreen`.
- `Settings` opens the settings dialog.
- `Mute All` mutes audio for both streams.
- `Unmute All` unmutes audio for both streams.
- `Unmute Main Stream / Mute Main Stream` toggles audio for the stream currently displayed in the main window.
- `Unmute PIP Stream / Mute PIP Stream` toggles audio for the stream currently displayed in the PIP window.
- Main/PIP mute toggles must follow the current layout after streams are swapped.
- `Swap feeds` swaps main/PIP roles.
- `Fullscreen` enters fullscreen.
- `Exit Fullscreen` exits fullscreen.

Audio behavior:

- Both streams must start muted on each app launch.
- Mute state is runtime-only unless the implementation explicitly adds persisted audio settings.
- Mute state must be remembered per stream during reconnects and stream restarts in the current app session.
- Muting or unmuting one displayed role must not unexpectedly change the other stream unless the user chooses `Mute All` or `Unmute All`.
- If the native playback library cannot independently mute two players inside one process, run each stream in a separate helper process and have the main app embed/control those helper windows.

Mouse/keyboard actions:

- Double-click inside the PIP rectangle swaps feeds.
- Double-click elsewhere in the main video window toggles fullscreen.
- Press `Esc` to exit fullscreen.

Important implementation note:

Native video surfaces may consume mouse events. Ensure right-click and double-click work over the live video itself, not only over non-video UI. Use the platform-appropriate event hook, native hit-test, overlay input layer, or input-capturing strategy.

## Fullscreen

Fullscreen behavior:

- Hide title bar and window chrome.
- Fill the display with the video area.
- Preserve aspect ratio where possible.
- Keep PIP visible.
- Exit fullscreen with `Esc`, double-click, or context menu.

## Settings Dialog

Implement a non-modal settings dialog.

The dialog must include:

- Text field for CCTV1 source URL.
- Text field for CCTV2 source URL.
- PIP size control.
- PIP X control.
- PIP Y control.
- PIP border color picker.
- PIP border size control with a 0 to 100 px range.
- Swap Streams button/control.
- Open Config button/control.
- Save button.
- Cancel button.

Behavior:

- PIP size, position, border color, and border size may preview immediately in the main window.
- Do not write setting changes to config until `Save`.
- `Save` writes changes to config.
- `Cancel` discards changes and restores the config-backed view.
- Closing the settings dialog without saving should behave like cancel.
- If either source URL changes on save, reload/restart the streams.
- Empty source URLs should be rejected.

## Config

Create or load a visible local config file. Preferred name:

```text
cctv-pip.properties
```

Required settings:

```properties
cctv1.url=rtsp://192.168.0.999:554/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
cctv2.url=rtsp://192.168.0.998:554/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
pip.border.color=#FFFFFF
pip.border.size=2
pip.x=1450
pip.y=40
pip.scale=0.28
reconnect.attempts=3
reconnect.delay.ms=1500
```

If the backend supports player-specific options, keep them independently configurable per stream, for example:

```properties
player.backend=native
player.options=
cctv1.player.options=
cctv2.player.options=
```

The exact key names can vary, but each stream must be independently configurable.

## No-Signal States

Before a stream connects, show:

```text
NO SIGNAL
```

If initial connection fails after retries, show:

```text
NO SIGNAL - Failed to connect
```

If a stream was live and later reconnect attempts fail, show:

```text
NO SIGNAL. Reconnection failed
```

Requirements:

- Show no-signal independently per stream.
- Show no-signal in the main area if the main stream fails.
- Show no-signal inside PIP if the PIP stream fails.
- Include the stream label, such as `CCTV1` or `CCTV2`.
- Include a short technical error reason when available.

## Reconnect

Implement independent reconnect logic for each stream:

- Default attempts: at least `3`.
- Default delay: `1500` ms.
- Reconnect must not freeze the UI.
- One failed stream must not block the other.
- Treat initial failure and failure after live playback differently.
- Only consider reconnect successful when actual playback resumes, not merely when a play command is issued.

## Error Reporting

Surface useful errors:

- Player/runtime not found.
- Unsupported option.
- RTSP timeout.
- Authentication failure.
- Stream not found.
- Decoder/player failure.
- Player rejected media item.

Do not silently hide all backend errors.

## Acceptance Criteria

- App launches and creates/loads config.
- App starts with CCTV1 main and CCTV2 PIP.
- Both streams start muted.
- Both default URLs use `subtype=0`.
- Main and PIP preserve aspect ratio.
- PIP has visible border.
- PIP is clamped within visible video area.
- Right-click context menu works over live video.
- Context menu order is Settings, separator, Mute All, Unmute All, separator, Unmute/Mute Main Stream, Unmute/Mute PIP Stream, separator, Swap feeds, Fullscreen/Exit Fullscreen.
- `Mute All` mutes both streams.
- `Unmute All` unmutes both streams.
- Main stream mute toggle affects whichever stream is currently displayed as the main video.
- PIP stream mute toggle affects whichever stream is currently displayed as the PIP video.
- Per-stream mute state survives reconnects and stream restarts during the current session.
- Double-click PIP swaps feeds.
- Double-click main video toggles fullscreen.
- `Esc` exits fullscreen.
- Settings dialog is non-modal.
- Settings can edit both source URLs.
- Save commits settings to config.
- Cancel discards settings.
- Source URL changes reload streams after save.
- No-signal states work independently.
- Reconnect works independently.
- CPU usage is materially lower than raw-frame/manual-painting approaches.
- Video quality is close to a native RTSP/H.264 player.
- If using an out-of-process stream host, building the main app also builds/copies the helper executable needed at runtime.
