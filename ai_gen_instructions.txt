## 3. Playback architecture and source responsibilities

Display two RTSP/H.264 streams. Stream1 initially fills the main view; Stream2 is
PIP. Both start muted every launch. Prioritize low CPU use, native/hardware-assisted
decoding, aspect ratio preservation, and native player quality. Do not re-encode
to MJPEG or manually copy/paint decoded full-resolution frames.

Use a shell and TWO SEPARATE stream-host processes. Each host owns exactly one
LibVLC instance, MediaPlayer, and VideoView. This is required to avoid the earlier
bug where audio changes affected both streams inside one process. The shell embeds
the hosts' real native windows and owns layout, menus, settings, and persistence.

Recommended source organization matching the snapshot:

- Program.cs: WinForms/LibVLC initialization, errors, logging lifecycle.
- MainForm.cs: stage, roles, menus, fullscreen, settings integration.
- CameraView.cs: video container and shell status overlay.
- HostedStreamProcess.cs: launch/find/embed/resize/control/stop one helper.
- MainWindowMouseHook.cs: native video mouse routing and occlusion checks.
- PipLayout.cs: pure percentage geometry.
- AppConfig.cs, PropertiesFile.cs, AppSettings.cs: persisted config and draft snapshot.
- OptionsForm.cs, SettingsFileOperations.cs: native settings and file operations.
- AppIcon.cs: shared embedded icon loader in namespace CctvPip.
- AppLog.cs, BudgetFileTarget.cs: shared logging in namespace CctvPip.
- CctvPip.StreamHost/{Program,HostOptions,StreamHostForm}.cs: helper implementation.
- Directory.Build.props/targets: shared four-part versions.
- .github/workflows/build-windows.yml and .github/scripts/release.cjs: releases.

The original source also has an UNUSED in-process StreamPlayer.cs with automatic
retry logic. MainForm does not instantiate it. Do not treat it as the active player
or replace process isolation with it. Recreating unused code is not required for
runtime equivalence; section 8 specifies the actual retry boundary.

## 4. Host launch, embedding, IPC, and shutdown

Use ProcessStartInfo.ArgumentList, UseShellExecute=false, and the helper directory
as working directory. Do not construct shell command strings. Launch:

```text
CctvPip.StreamHost.exe --hosted --stream cctv1 --label CCTV1 --config <active-config-path>
CctvPip.StreamHost.exe --hosted --stream cctv2 --label CCTV2 --config <active-config-path>
```

Add --unmuted only if that controller remembers an unmuted state. Pass the shared
logging environment variables from section 12. Resolve the helper first under
StreamHost beside the viewer, then beside the viewer, then from the helper's
development bin/Debug/net8.0-windows output as a fallback.

Hosted windows are borderless, ShowInTaskbar=false, initially off-screen at
(-32000,-32000), but create a real native window. Wait up to 8 seconds, polling
about every 50 ms, checking early process exit. Try MainWindowHandle AND enumerate
visible top-level windows by process ID and expected title prefix. MainWindowHandle
alone may remain zero for off-screen/borderless helper windows.

Embed with SetParent into the matching shell VideoView.Handle, add WS_CHILD and
WS_VISIBLE, remove WS_POPUP, show the host, and MoveWindow to fill the video surface.
Resize both hosts on every layout change.

Use native message WM_APP+321 (0x8000+321), wParam values:

| Value | Action |
| --- | --- |
| 1 | Mute |
| 2 | Unmute |
| 3 | Restart playback inside this helper |
| 4 | Shut down this helper |

The shell's Reconnect stops/starts the selected helper PROCESS, preserving its
controller and audio state. Standalone Restart recreates the MediaPlayer within
the same process. Do not confuse these two actions.

On shutdown, clear stored process/window references, send command 4 if possible,
wait 1500 ms, Kill(entireProcessTree:true) if still running, wait another 1500 ms,
and dispose the Process. Unsubscribe resize handlers. Closing the viewer disposes
both hosts, settings, menus, and the mouse hook. The snapshot's discovery/shutdown
waits are synchronous; do not promise asynchronous/nonblocking host startup.

### Alt+Tab workaround

ShowInTaskbar=false alone previously left two blank helper entries in Alt+Tab.
Override StreamHostForm.CreateParams: for --hosted, add WS_EX_TOOLWINDOW (0x80)
and remove WS_EX_APPWINDOW (0x40000). Apply on FIRST native handle creation and
every recreation, not just after embedding. Only the viewer should appear in the
taskbar/Alt+Tab for hosted operation. Standalone hosts remain normal windows there.

## 5. Window, stage, PIP geometry, DPI, and fullscreen

Main form: black, centered initially, minimum outer size 960x620. Initial client
width=min(1920,max(960,primaryWorkingArea.Width-80)); client height=
min(1166,max(620,primaryWorkingArea.Height-80)). Center the largest 16:9 stage inside
the client area, with black letterboxing/pillarboxing. Main camera fills that stage
without border/padding. PIP overlays it and is brought to front after layout.
Its panel background is border color; Padding supplies border thickness.

PIP position is measured from the MAIN VIDEO STAGE, not desktop/monitor pixels,
outer form bounds, or the leftover travel after subtracting PIP dimensions:

```text
xRequested = round(stageWidth  * pip.left.percent / 100)
yRequested = round(stageHeight * pip.top.percent  / 100)
```

Thus 10%/10% in an area 1000x500 gives (100,50); doubling the area to 2000x1000
gives (200,100), before clamping.

Exact PipLayout rules:

- Non-positive stage width/height returns Rectangle.Empty.
- Finite pip.scale clamps to 0..1; non-finite scale falls back to .28.
- width=min(stageWidth,max(160,round(stageWidth*scale))). A displayed size of 0%
  still gives the minimum visible PIP, capped by stage size, rather than hiding it.
- height=max(1,round(width/(16/9))). If too tall, use stageHeight and recalculate
  width from that height/aspect, capped inside the stage.
- Finite left/top percentages clamp 0..100. The geometry helper uses 0 for
  non-finite margins; AppConfig instead supplies safe defaults 70/4.
- Clamp displayed X into 0..stageWidth-width and Y into 0..stageHeight-height.
  The WHOLE PIP stays inside the stage, including border.
- Never rewrite requested/saved percentages as a result of display clamping.
  At 100%/100%, display bottom-right but keep the settings at 100/100.
- Default scale=.28, left=70%, top=4%, border=#FFFFFF, thickness=2 px.
- Thickness clamps to 0..100 px; 0 removes it. It is a file-only setting in the
  current settings redesign, not a visible thickness control.

Recalculate on Resize and on DpiChanged. Queue ApplyLayout with BeginInvoke AFTER
WinForms handles DPI scaling. Maximize/restore/fullscreen and moves between mixed
4K/1080p/DPI monitors must keep proportional position and size without saved drift.

Swap changes display roles only, never reconnects sources or transfers mute state.
Fullscreen saves Bounds, FormBorderStyle, WindowState, TopMost; clears minimum size;
sets normal WindowState, borderless, Screen.FromControl(this).Bounds, TopMost=true.
Exit restores those values and minimum 960x620. Normal windowed mode is coverable
by other applications. Double-click main, menu, and Esc support entry/exit as below.

## 6. Mouse routing and covered-window bug fix

Native surfaces consume ordinary WinForms mouse events. Handle right-click and
double-click over LIVE embedded video as well as non-video areas using a
WH_MOUSE_LL (14) hook for WM_LBUTTONUP (0x202) and WM_RBUTTONUP (0x205). Keep its
delegate alive, unhook on disposal, always CallNextHookEx, and do not swallow input.

Rectangle-only hit-testing caused the viewer to steal clicks through another app
and jump to the front. Validate BEFORE queuing and AGAIN inside the UI callback:

- Owner handle exists, owner is visible/not disposed/not minimized.
- Click is inside its client rectangle and passes the UI action guard.
- Suppress handling while the context menu is open and over the visible settings
  form's bounds. Settings/color/file interactions must not toggle/swap video.
- WindowFromPoint(original SCREEN point) must return owner.Handle or a native
  IsChild(owner.Handle,window) descendant. Native ancestry is required: embedded
  playback descendants belong to other processes, while unrelated same-process
  forms must be rejected. Process equality or screen rectangle is insufficient.
- Reset pending double-click state on any rejected click.

Use SystemInformation.DoubleClickTime and DoubleClickSize. A qualifying pair inside
PIP swaps feeds; elsewhere in the main client toggles fullscreen. Marshal actions
using BeginInvoke, tolerate owner disposal, and cancel if a covering window appears
before execution. A rejected click must never activate/raise the viewer.

## 8. Playback lifecycle, failures, and standalone host

Core.Initialize() initializes LibVLC. Construct each host's LibVLC with configured
global options. StartPlayback stops/disposes the old MediaPlayer, creates one with
EnableHardwareDecoding=true, attaches it to VideoView, applies audio, constructs
Media from URL, adds that source's media options, calls Play, then disposes Media.
Dispose player, menu, and LibVLC on closing.

Actual active-path statuses:

- Shell CameraView initially shows label and NO SIGNAL.
- Starting helper: STARTING HOST. Launch/window-discovery failure: HOST START FAILED
  plus short technical detail when available.
- After embedding, shell hides its own overlay. Host ready does NOT prove RTSP
  playback; the host shows the actual connection/playback state.
- Host shows STARTING, hides overlay on Playing, and reapplies mute state.
- EncounteredError -> PLAYER ERROR; EndReached -> STREAM ENDED; false Play return
  -> PLAY REJECTED; a thrown playback exception -> its message in the UI.
- Host status includes label/PID; title includes label, Muted/Unmuted, PID. Marshal
  playback UI changes to the UI thread. Shell error detail is normalized to one
  line and truncated after 240 characters.

IMPORTANT COMPATIBILITY BOUNDARY: the active hosted implementation has NO automatic
retry timer/attempt loop or continuous child-exit supervision. reconnect.attempts
and reconnect.delay.ms remain legacy properties but are not consumed by the active
host. The earlier instruction file's automatic retries and distinct
'NO SIGNAL - Failed to connect'/'NO SIGNAL. Reconnection failed' requirements refer
to the unused in-process player. Reproduce manual per-source Reconnect; adding
automatic retries would change this snapshot's behavior.

Without --hosted the helper is a centered normal window, client 960x540, minimum
480x270, shown in taskbar and Alt+Tab. Right-click: Mute/Unmute, separator, Restart.
M toggles mute; R restarts. Starts muted unless --unmuted is present. Arguments:

| Argument | Meaning |
| --- | --- |
| --stream cctv1 or cctv2 | Select prefix; default cctv1 |
| --config <path> | Explicit file; default stream-pip.config beside helper |
| --url <url> | Source override; first positional argument also supplies URL |
| --label <text> | Label override; defaults CCTV1 Host / CCTV2 Host |
| --libvlc-options <list> | Override global comma-separated options |
| --media-options <list> | Override selected-source comma-separated options |
| --unmuted | Start with audio |
| --hosted | Borderless embedded mode and Alt+Tab suppression |

Parse argument keys case-insensitively; trim/lowercase stream selection. Resolve
URL/options from CLI, then nonblank selected config entries, then defaults. Split

### Percent and color controls

Size, Left, and Top each pair TrackBar/NumericUpDown, range 0..100. Numeric controls
have 2 decimals, increment .1, and right-aligned text. TrackBars use integer values
and ticks every 10 on both sides. Numeric edits keep fractional draft values while

Prefer executable directory; if load/create/save there fails, use
%LOCALAPPDATA%/CctvPip/stream-pip.config. Show/pass the actual resolved path.

If new filename is absent and cctv-pip.properties exists in that directory, MOVE
the old file to stream-pip.config before loading. If both exist, prefer new and
leave old alone. Keep existing values, append missing defaults, save at startup.

New-file defaults, exactly:

```properties
cctv1.url=rtsp://192.168.0.999:554/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
cctv2.url=rtsp://192.168.0.998:554/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
```

The .999/.998 addresses are intentional non-working placeholders, not private real

backend is LibVLC. Legacy getters keep reconnect.attempts>=3 and delay>=250 ms, but
the hosted implementation does not use them for retries (section 8).

Properties parser: case-insensitive keys, last duplicate wins; split at first = or :;
trim key/value; preserve blank lines, #/! comments, unparsed lines, and entry order.
Save property entries as key=value. Remove must remove ALL case-insensitive duplicates.
Use invariant-culture numbers. Non-finite/malformed margin values default to 70/4,
then clamp 0..100; invalid scale uses .28, with layout applying its clamp. Border
thickness clamps 0..100; invalid/blank config color falls back to white. The helper
uses a read-only = parser skipping blank/#/; lines; canonical saved files work in both.

### One-time migration from pip.x/pip.y

Old pixel keys are migration INPUT only. Per axis, if no percentage is already
present, wait for the initial fitted stage dimensions. Calculate initial PIP size,
clamp old pixel X/Y to the visible range, convert pixelOffset*100/stageDimension,
and save invariant with up to 3 decimals. Legacy fallback X=1450/Y=40. Explicit
percentages win PER AXIS. Do not insert a percentage default on an axis containing
a legacy pixel key before migration, or its intended position would be lost.

After valid initialization, remove EVERY pip.x/pip.y occurrence even if percentages
were already present; save only if conversion/cleanup changed data. Never recreate
these keys. Resize does not rerun migration or rewrite settings. Save/export also
remove obsolete keys. New configurations use only percentage defaults.

Dialog persistence uses scale up to 4 decimals, margins up to 2, and #RRGGBB color.
AppConfig.Dispose MUST NOT save its stale snapshot: doing so previously overwrote
changes the user had just made externally in Notepad. Save explicitly and merge
current disk values for fields not controlled by the dialog.

## 12. NLog configuration, filenames, shared retention, and failures

Use NLog 6.2.1 plus a registered custom TargetWithLayout named BudgetFile. Standard
per-file size/file-count retention is not a combined folder-byte limit. Implement
the following inside the NLog target shared by viewer and helpers.

logging.config is independent of stream-pip.config and sits beside the viewer.
Copy it to build/publish output; helper links the same default file. Register
BudgetFile before parsing the XML. Default configuration:

```xml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      throwConfigExceptions="true">
  <targets>
    <target xsi:type="BudgetFile" name="session"
            layout="${longdate}|${level:uppercase=true}|PID ${processid}|${logger}|${message}" />
  </targets>
  <rules>
    <logger name="*" minlevel="Info" writeTo="session" />
  </rules>
</nlog>
```

Changes apply on next app/process start, not live reload. NLog severity levels
include Trace, Debug, Info, Warn, Error, Fatal, Off; existing events use Info/Warn/Error.
Missing config uses defaults. XML/NLog config or file-read errors fall back to
defaults and safely log 'Invalid logging.config; using default logging'. If no
BudgetFile target named session exists, add one with an Info-through-Fatal rule.
Set its directory/session programmatically to enforce the required destination.

Location is logs beside the MAIN executable for viewer and hosted children.
A standalone diagnostic helper uses logs beside ITS executable. LocalAppData stream
config fallback does not relocate logging.

File naming uses local startup time:

```text
yyyyMMddHHmmss_streampipviewer_log.txt
20270112132522_streampipviewer_log.txt
```

Example: 12 January 2027 at 13:25:22. Every generated filename must match
^\d{14}_streampipviewer_log\.txt$. A new viewer session starts a fresh file. Write
UTF-8 without BOM with platform newlines. The shell explicitly passes:

- STREAM_PIP_LOG_DIRECTORY: normalized full shared logs directory.
- STREAM_PIP_LOG_SESSION: viewer's INITIAL session filename, not a full path.

Children use that directory, load logging.config from its parent, and initially
append to that shared file. Only accept inherited session names matching the regex.
The controller retains its initial filename for later children even after its
target rolls. Separate viewer instances also coordinate at directory level.

Exact target algorithm:

1. MaximumDirectoryBytes=25*1024*1024=26,214,400 (25 MiB).
2. RollBytes=1024*1024. Render complete event/newline and measure UTF-8 bytes BEFORE
   append. If one event exceeds 1 MiB, replace it with 'Log event omitted: exceeds
   1 MB.' plus newline instead of breaking the limit.
3. Protect initialization, name allocation, cleanup, rotation, and appends with a
   named mutex Local\StreamPipLogs_ + uppercase hex SHA256 of the UTF-8 full directory
   path uppercased invariantly. Wait up to 5 seconds; treat abandoned mutex as
   acquired. On timeout skip the operation. Release in finally; dispose on close.
4. Initialize directory and clean excess pre-existing files. Unless a valid inherited
   session exists, allocate the new filename atomically with FileMode.CreateNew.
5. On name collision increment candidate time by one SECOND until unused. Preserve
   filename shape: no PID, sequence suffix, alternate extension, or overwriting.
6. Before append, if current length+event bytes exceeds 1 MiB, allocate another file
   using the same name algorithm. Processes may roll independently after sharing
   the initial file, but all still share the combined folder budget.
7. Recursively count ALL files under logs, skipping reparse points. Sort by oldest
   LastWriteTimeUtc then ordinal filename. Delete oldest files until total+incoming
   bytes<=MaximumDirectoryBytes. This is a dedicated disposable folder: nonstandard
   files count too and are subject to cleanup, not just the current name pattern.
8. If deletion fails due to I/O/access errors, try remaining files. If insufficient
   room can be made, skip the write rather than exceed the budget; resume when
   cleanup becomes possible. Pre-existing locked/external files cannot be removed
   against Windows permissions and may prevent immediate reduction of an oversized
   folder. Do not imply cleanup can override those locks.
9. Append synchronously under the mutex using FileShare.Read, then close the handle.
   No persistent writers, delayed queues, or independent 25 MiB budgets per helper.

Cleanup runs on initialization and every write, not a periodic timer. Do not send
NLog internal diagnostics or other unbudgeted writers into logs. Executable directory
must be writable; no alternate log-folder fallback is implemented other than the

## Appendix A. Exact binary icon assets

Records below contain original tracked Base64 bytes, SHA-256, and byte count.
Decode them; do not redraw or request missing icons. The README screenshot and
unused icon_save16.png are not runtime resources and are not required here.

Extract this file's asset records into a new project with PowerShell 7:

```powershell
$instructionText = [IO.File]::ReadAllText((Join-Path $PWD 'ai_gen_instructions.txt'))
$assetPattern = '(?ms)^@@ASSET (?<path>assets/[A-Za-z0-9_-]+\.(?:ico|png)) (?<hash>[A-F0-9]{64}) (?<length>\d+)\r?\n(?<data>.*?)^@@ENDASSET\r?$'
foreach ($assetMatch in [regex]::Matches($instructionText, $assetPattern)) {
    $assetBytes = [Convert]::FromBase64String($assetMatch.Groups['data'].Value)
    $assetHash = [Convert]::ToHexString([Security.Cryptography.SHA256]::HashData($assetBytes))
    if ($assetBytes.Length -ne [int]$assetMatch.Groups['length'].Value -or
        $assetHash -ne $assetMatch.Groups['hash'].Value) { throw 'Asset checksum mismatch.' }
    $assetDestination = Join-Path $PWD $assetMatch.Groups['path'].Value
    [IO.Directory]::CreateDirectory([IO.Path]::GetDirectoryName($assetDestination)) | Out-Null
    [IO.File]::WriteAllBytes($assetDestination, $assetBytes)
}
```
